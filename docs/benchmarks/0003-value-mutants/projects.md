## Why this scope

- **es-toolkit** (String (docs/reference/string, main es-toolkit entry, not compat)): The string reference pages state many concrete example inputs and outputs. 17 of the 22 string pages were taken; dedent, lowerFirst, upperFirst, trimStart and trimEnd were left out.
- **defu** (README Usage, Custom Merger, Function Merger, Array Function Merger, Remarks): defu is a small library; all four documented runtime exports live in src/defu.ts and the README states concrete example inputs and outputs, skipped keys and merge rules.
- **valibot** (Actions (validation actions on length, size/bytes and value) from the API reference menu (website/src/routes/api/menu.md)): The string-format action pages (email, hexColor, ...) state no concrete values, so the length and value validation actions were taken instead; their pages state numbers (3, 32, 8, 100, 64) and the length unit (UTF-16 code units).
- **cron-parser** (README sections Cron Format, Predefined Expressions, Options, Date Range Handling, Strict Mode, Hash support, Field Manipulation and Crontab File Operations): The README states concrete values for predefined expressions, strict mode error messages, date-range handling and field-override results; these are the value-heavy operations of the parser, expression, field collection and file parser classes.
- **neverthrow** (Synchronous API (`Result`)): The README's Synchronous API section documents ok, err and the Result methods; the methods are declared on the Ok and Err classes in src/result.ts, so each documented method is mapped to the variant whose behaviour the docs state.
- **jotai** (jotai/utils (the docs/utilities pages: storage, resettable, lazy, async, select, split)): The utilities pages state concrete defaults and behaviours (default storage, getOnInit false, RESET, unwrap fallback, selectAtom Object.is default, splitAtom actions). Operations whose docs only show usage without stated outcomes (atomWithReducer, atomWithObservable, freezeAtom) were left out.
- **react-hook-form** (React hooks API (react-hook-form.com/docs)): The repo's own docs are thin and nearly all helpers under src/logic and src/utils are anonymous default exports, so the documented hooks were taken; their pages state concrete defaults, return shapes and examples.
- **react-hotkeys-hook** (the public exports of react-hotkeys-hook (useHotkeys, isHotkeyPressed, useRecordHotkeys, HotkeysProvider, useHotkeysContext)): The API pages list every option with its default and the modifier, sequence and scope rules with concrete values. Internal helpers in parseHotkeys.ts and validators.ts are not documented as public API, so they are out of scope.
- **h3** (Utils: Security > Path, plus Response > Sanitize and More Response Utils): The Path utilities and the redirect and no-content helpers state many concrete values (status codes, header names, example inputs and outputs). The CORS and cookie sections of the docs state almost no values, so they were left out.
- **express-rate-limit** (Configuration reference (option defaults), Helpers, and the Time constants subsection): The configuration docs state many concrete defaults (window, limit, message, status code, headers, property name); the helper doc states the ipKeyGenerator default subnet and IPv4 handling; the time constants are the documented millisecond units.
- **cac** (README: Usage and References (CLI Instance and Command Instance)): The README References section documents each CLI and Command method with its type, defaults (customFlags, argv) and example inputs. Methods are taken from the CAC and Command classes.

Edits made to the agent's guarantees before freezing are in `notes/guarantee-edits.md`.
